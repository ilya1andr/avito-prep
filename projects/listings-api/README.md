# Listings API

REST API для управления объявлениями (аналог сервиса объявлений Авито).

Проект написан на **Go** с использованием **PostgreSQL** и слоистой архитектуры.

## Стек

- **Язык:** Go 1.22+
- **База данных:** PostgreSQL 16 (в Docker)
- **Миграции:** golang-migrate
- **Архитектура:** Handler → Service → Repository

## Запуск проекта

### 1. Запустите PostgreSQL в Docker

```bash
docker run --name pg \
  -e POSTGRES_PASSWORD=secret \
  -p 5432:5432 \
  -d postgres:16
```

### 2. Примените миграции

Создайте таблицы в базе данных:

```bash
migrate -path migrations \
  -database "postgres://postgres:secret@localhost:5432/postgres?sslmode=disable" \
  up
```

### 3. Запустите сервер

```bash
go run .
```

После запуска сервер будет доступен по адресу:

```text
http://localhost:8080
```

## API

### 1. Проверка работоспособности

**GET `/health`**

Возвращает статус сервера.

**Ответ:**

```json
{
  "status": "ok"
}
```

---

### 2. Создать объявление

**POST `/listings`**

**Тело запроса:**

```json
{
  "title": "MacBook Pro",
  "price": 150000
}
```

**Ответ:** `201 Created`

Возвращает JSON с созданным объявлением, включая его `id`.

Пример:

```json
{
  "id": 1,
  "title": "MacBook Pro",
  "price": 150000
}
```

---

### 3. Получить список объявлений

**GET `/listings`**

Поддерживается фильтрация по цене.

#### Query-параметры

- `min_price` — минимальная цена
- `max_price` — максимальная цена

**Пример запроса:**

```text
GET /listings?min_price=10000&max_price=50000
```

**Ответ:** `200 OK`

Возвращает JSON-массив объявлений.

---

### 4. Получить объявление по ID

**GET `/listings/{id}`**

Возвращает объявление по указанному ID.

Если объявление не найдено, возвращается:

```text
404 Not Found
```

---

### 5. Обновить объявление

**PUT `/listings/{id}`**

**Тело запроса:**

```json
{
  "title": "MacBook Air",
  "price": 100000
}
```

**Ответ:** `200 OK`

Возвращает обновленное объявление.

---

### 6. Удалить объявление

**DELETE `/listings/{id}`**

Удаляет объявление по указанному ID.

**Ответ:** `204 No Content`

## Архитектура

Проект построен с использованием слоистой архитектуры:

```text
Handler → Service → Repository → PostgreSQL
```

- **Handler** — принимает HTTP-запросы, валидирует входные данные и формирует HTTP-ответы.
- **Service** — содержит бизнес-логику приложения.
- **Repository** — отвечает за взаимодействие с базой данных.
