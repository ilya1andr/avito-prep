# Search in Rotated Sorted Array (LeetCode 33)

Дата решения: 27 октября 2026
Тема: Бинарный поиск.

## Условие
Дан отсортированный массив, который "прокрутили" (например, [4,5,6,7,0,1,2]). Найти индекс числа target за O(log n).

## Решение

```python
class Solution(object):
    def search(self, nums, target):
        l = 0
        r = len(nums) - 1
        
        while l <= r:
            mid = (l + r) // 2
            
            if nums[mid] == target:
                return mid
                
            # Левая половина отсортирована
            if nums[l] <= nums[mid]:
                # Проверяем, лежит ли target внутри этой половины
                if nums[l] <= target < nums[mid]:
                    r = mid - 1
                else:
                    l = mid + 1
            # Правая половина отсортирована
            else:
                # Проверяем, лежит ли target внутри этой половины
                if nums[mid] < target <= nums[r]:
                    l = mid + 1
                else:
                    r = mid - 1
                    
        return -1
   ```

## Ключевая идея
Стандартный бинарный поиск не работает, так как массив "сломан". На каждом шаге мы определяем, какая из половин (левая или правая) точно отсортирована.
Если `nums[l] <= nums[mid]`, значит левая половина в порядке. Мы проверяем, лежит ли `target` в диапазоне `[nums[l], nums[mid]]`. Если да — идем влево, если нет — вправо.
Если левая половина сломана, значит правая точно отсортирована, и мы делаем то же самое для неё.

## Где я споткнулся
- Сначала забыл про нижнюю границу: проверял только `target < nums[mid]`, из-за чего терял элементы. Правильно: `nums[l] <= target < nums[mid]`.
-Выходил за пределы, когда использовал `while l < r` вместо `while l <= r` (пропускал последний элемент).

## Что запомнить
-Условие `while l <= r` гарантирует, что мы проверим все элементы.
-Всегда проверяем диапазон двумя границами (и левую, и правую).

## Сложность
Время: O(log n) — отсекаем половину массива на каждом шаге.
Память: O(1).
