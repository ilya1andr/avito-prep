# Неделя 9. Конспект (Транзакции, Сети, Связные списки)

## 1. Транзакции и ACID

- **Транзакция** — последовательность операций, которая выполняется по принципу «всё или ничего».
- **ACID:**
    - **A (Atomicity):** Атомарность (всё или ничего).
    - **C (Consistency):** Согласованность (данные не ломаются).
    - **I (Isolation):** Изолированность (транзакции не мешают друг другу).
    - **D (Durability):** Надежность (если база подтвердила запись, она не пропадет при сбое).
- **Золотое правило:** Всегда использовать `defer tx.Rollback(ctx)`. Если программа упадет до `Commit`, Rollback отменит все изменения.

**💻 Синтаксис в Go:**

```go
// 1. Начинаем транзакцию (дефолтный уровень изоляции Read Committed)
tx, err := conn.Begin(ctx)
if err != nil {
    return err
}

// 2. Обязательно ставим отложенный откат
defer tx.Rollback(ctx)

// 3. Выполняем запросы. ВАЖНО: используем tx, а не conn!
_, err = tx.Exec(ctx, "UPDATE accounts SET balance = balance - 100 WHERE id = 1")
if err != nil {
    return err
}

// 4. Фиксируем изменения
err = tx.Commit(ctx)
if err != nil {
    return err
}
```

## 2. Уровни изоляции (аномалии)

- **Грязное чтение (Dirty Read):** Одна транзакция видит данные другой, которая еще не закоммичена. (Лечится уровнем `Read Committed` и выше).
- **Неповторяющееся чтение (Non-repeatable Read):** В одной транзакции прочитал строку дважды, и значение изменилось (кто-то сделал UPDATE). (Лечится `Repeatable Read`).
- **Фантомное чтение (Phantom Read):** В одной транзакции сделал запрос COUNT(*), а количество строк изменилось (кто-то сделал INSERT). (Лечится `Serializable`).
- **Дефолтный уровень в PostgreSQL:** `Read Committed`.

**💻 Синтаксис в Go (как поменять уровень):**

```go
tx, err := conn.BeginTx(ctx, pgx.TxOptions{
    IsoLevel: pgx.Serializable, // Самый строгий уровень
})
```

## 3. Сети (Теория)

- **TCP vs UDP:**
    - TCP — надежный, гарантирует доставку и порядок (HTTP, базы данных).
    - UDP — быстрый, без гарантий (видео, игры, HTTP/3).
- **HTTP/1.1 vs HTTP/2 vs HTTP/3:**
    - 1.1: Очередь запросов, блокировки.
    - 2: Мультиплексирование в одном TCP-соединении (стандарт в Авито).
    - 3: То же, но поверх UDP (быстрее в мобильных сетях, нет HOL-блокировки).
- **HTTPS и TLS:** Шифрование трафика. Сертификат — это «паспорт» сервера (выданный удостоверяющим центром), который подтверждает, что сервер настоящий.
- **Идемпотентность:** GET, PUT, DELETE — можно повторять. POST — нельзя (создаст дубликаты).

## 4. Сети в Go (http.Server и таймауты)

- Обычный `http.ListenAndServe` работает вечно и не имеет таймаутов. В продакшене используют `&http.Server{}`.
- **Зачем таймауты:**
    - `ReadHeaderTimeout` — защита от «медленных» клиентов (Slowloris). Если клиент подключился, но не прислал заголовки за N секунд — сервер рвет соединение.
    - `ReadTimeout` — ограничивает время чтения всего запроса (включая тело).
    - `WriteTimeout` — защита от медленной отправки ответа.
    - `IdleTimeout` — сколько сервер держит бездействующее keep-alive соединение.

**💻 Синтаксис в Go:**

```go
server := &http.Server{
    Addr:              ":8080",
    Handler:           mux,
    ReadHeaderTimeout: 2 * time.Second,
    ReadTimeout:       5 * time.Second,
    WriteTimeout:      10 * time.Second,
    IdleTimeout:       120 * time.Second,
}

log.Fatal(server.ListenAndServe())
```

## 5. Миграции баз данных

**💻 Синтаксис (golang-migrate):**

- Создать: `migrate create -ext sql -dir migrations -seq create_my_table`
- Применить: `migrate -path migrations -database "postgres://..." up`
- Откатить: `migrate -path migrations -database "postgres://..." down 1`
- *Зачем:* Версионирование структуры БД. Утилита записывает номер примененной миграции в таблицу `schema_migrations`.

## 6. Алгоритмы (Связные списки)

- **Reverse Linked List (206):** Три указателя (`prev`, `curr`, `next`). Сохраняем следующий узел, переворачиваем стрелку, сдвигаем указатели.
- **Merge Two Lists (21):** Dummy node (фиктивный узел) в начале, чтобы не писать кучу `if`. Сравниваем и прицепляем меньший узел.
- **Linked List Cycle (141):** Черепаха и заяц. `slow` делает 1 шаг, `fast` делает 2. Если встретились — есть цикл. Память O(1).
- **Remove Nth Node (19):** Dummy node. `fast` убегает на `n+1` шаг вперед, затем `fast` и `slow` идут вместе. Когда `fast` дойдет до `None`, `slow` будет стоять ровно перед удаляемым узлом.
- **Palindromic Linked List (234):** Найти середину (черепаха и заяц), развернуть вторую половину, сравнить с первой.

**💻 Синтаксис (Паттерн «Черепаха и заяц»):**

```python
slow = head
fast = head

while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
```

## 7. Где я спотыкался (Личные заметки)

- `main redeclared`: Нельзя держать два файла с `func main()` в одной папке (удалил `tx_demo.go`).
- `Connected` в PowerShell: Свойство `$client.Connected` в PowerShell не проверяет реальное состояние сети. Оно возвращает `true`, даже если сервер уже разорвал связь. Нужно всегда использовать `Read()`.
- **🔥 Тест таймаута:** Мы проверяли таймаут через PowerShell. Создавали `TcpClient`, отправляли начало заголовков, ждали 3 секунды и отправляли остаток. Ошибки не было!
    - **Почему:** Метод `$stream.Write()` пишет данные в **буфер операционной системы Windows**, а не напрямую в сеть. ОС говорит «всё ок», даже если сервер уже закрыл соединение.
    - **Как проверить правильно:** Нужно использовать `$stream.Read()`. Если сервер разорвал соединение, `Read()` вернет `0` (или кинет ошибку). Именно это и доказало, что `ReadHeaderTimeout` работает.
