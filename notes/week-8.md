# Неделя 8. Конспект (Миграции, Фильтры, Валидация, Тесты с моками)

## 1. Миграции базы данных
- **Проблема:** Создавать таблицы вручную через `psql` — плохо. Если завтра нужно будет добавить колонку, придется просить коллег делать это вручную, а на новом сервере база вообще будет пустой.
- **Решение:** Использовать утилиту `golang-migrate`.
- **Как работает:** В папке `migrations` лежат файлы `000001_name.up.sql` (создать) и `.down.sql` (откатить). Утилита применяет их по очереди и записывает в таблицу `schema_migrations`, какие версии уже применены.
- **Зачем:** Версионирование структуры БД (как Git для кода). Можно откатить (`migrate down`) или накатить (`migrate up`).
- **Важно:** `listing_repo.go` (с SQL-запросами) и `migrate` (создание таблиц) не конфликтуют. Репозиторий *работает* с данными, а миграции *создают структуру*.

## 2. Динамический SQL (Фильтрация)
- **Задача:** Клиент передает `?min_price=100&max_price=500`. Нужно вернуть только подходящие объявления.
- **Проблема:** Мы не знаем заранее, какие фильтры придут. Писать `WHERE price >= $1` нельзя, если `min_price` не передан.
- **Решение:**
    - Создаем массивы `args` (значения для $1, $2) и `conditions` (текст условий).
    - Если `minPrice != nil`, добавляем `price >= $1` и аргумент.
    - Склеиваем через `strings.Join(conditions, " AND ")`.
    - **Почему указатели (`*int`):** `nil` однозначно означает «фильтр не передан». Число `0` — это валидная цена (бесплатно), поэтому обычный `int` не подошел бы.

## 3. Обработка Query Parameters в Хендлере
- **`r.URL.Query().Get("min_price")`** — достает значение из URL (всегда возвращает строку).
- **`strconv.Atoi()`** — превращает строку в число. Если клиент передал `abc`, возвращает ошибку, и мы отдаем `400 Bad Request`.
- **`r.PathValue("id")`** — достает ID из URL (`/listings/5` -> `"5"`), которое мы задали в роуте как `{id}`.

## 4. Валидация (Бизнес-логика)
- Проверки всегда живут в **Сервисе**, а не в Хендлере.
- **Что проверяли:**
    - `strings.TrimSpace(title)` — удаляем пробелы, чтобы строка `"   "` считалась пустой.
    - Длина названия < 100 символов.
    - Цена > 0 и не больше 10 000 000.
- **Ошибки возвращаем через `errors.New()`**, Хендлер их ловит и отдает `400 Bad Request`.

## 5. CRUD (Update и Delete)
- **Update (PUT):** `UPDATE listings SET title = $1, price = $2 WHERE id = $3 RETURNING id, title, price`.
    - `RETURNING` — фишка PostgreSQL, возвращает обновленную строку, чтобы отдать ее клиенту.
- **Delete (DELETE):** `DELETE FROM listings WHERE id = $1`.
    - Используем `Exec`, который возвращает `cmdTag.RowsAffected()`. Если `0` — значит, ничего не удалили (отдаем 404 Not Found).
    - **Код ответа 204 No Content** — стандарт REST при удалении (тела нет).

## 6. Тесты и Моки (Главное!)
- **Проблема:** Сервис жестко зависел от реального Репозитория (и базы данных). Тесты были бы медленными и требовали бы Docker.
- **Решение:**
    1. Создали интерфейс `ListingRepositoryInterface` в репозитории.
    2. Сервис теперь принимает интерфейс (`repo repository.ListingRepositoryInterface`), а не конкретный `*ListingRepository`.
    3. В тестах создали `mockRepo` (подделку), которая реализует этот интерфейс, но ничего не пишет в БД.
- **Почему без `*`:** Интерфейс в Go — это уже ссылочный тип. Писать `*ListingRepositoryInterface` нельзя.
- **Почему `&mockRepo{}`:** Методы мока определены на указателе, поэтому передаем адрес.

## 8. Алгоритмы
- **Non-overlapping Intervals (435):** Жадный алгоритм. Сортируем по **концу** интервала (`x[1]`). Если пересекаются, удаляем текущий, а его конец приравниваем к предыдущему.
- **Kth Largest Element (215):** Min-Heap (куча) размера `k`. Проходим по массиву, добавляем в кучу, а если размер > k — выкидываем самый маленький (верхний). Наверху останется K-й по величине элемент. В Python это `heapq`, в Go — пакет `container/heap` (требует написания методов `Len`, `Less`, `Swap`, `Push`, `Pop`).
